# Aster · 桌面机器人

轻量 macOS 桌宠，监听本机 Codex、Claude Code、Cursor、Kiro 和通过包装命令启动的 CLI。无需模型 API Key。

## 使用

打开 `release/Aster-darwin-arm64/Aster.app`。

- 默认只有 200 × 320 的透明悬浮窗，显示 3D 小机器人和状态数量。首次打开位于屏幕右上角；拖动后自动记住位置，重启恢复。外接屏断开时回到可见屏幕。
- 默认待机有呼吸、眨眼、转头和偶尔招手。进行中呈蓝色并交替摆动双手；完成呈绿色，短暂举手庆祝；失败呈红色并摇头。待授权呈琥珀色举手，待输入呈紫色侧头倾听，待确认呈橙色摊手；中断、待核实和离线有各自的灰色姿态。颜色作用于眼睛、天线和胸灯。
- 多任务时机器人优先展示待授权、失败、待输入、待确认，再展示进行中；没有这些状态时采用最近任务的结果，没有任务时回到待机。按时长设置隐藏的任务不影响机器人。设置中的「减少角色动作」以及系统减少动态效果均会停止动作，保留状态颜色和姿态。
- 点击机器人展开 380 × 490 的任务列表；再次点击、点击外部或按 Escape 收起。
- 按工具和状态筛选；待授权和等待输入优先展示。
- 点击 Codex 任务直达对应任务。其他来源视可用信息打开项目或定位原终端标签，不自动执行命令。
- 菜单栏星形图标可显示、隐藏桌宠或退出。列表右上角设置可更名、减少动作、开启完成/失败通知。

设置中的「历史任务隐藏时间」可选择 3 天、7 天、1 个月（30 天）或始终显示（默认）。已完成任务从最新一轮完成时计时；失败、中断、空闲、状态未知和待核实任务按最后更新时间计时。到期后自动从列表、状态数量和桌宠提示中隐藏；进行中、待授权、等待输入和等待确认的任务仍然显示。不删除原任务，再次运行或更新后重新显示。设置会自动保存，旧版 24 小时及以内的选项会迁移为 3 天。

## 状态与兼容范围

| 来源 | 监听方式 | 点击定位 |
|---|---|---|
| Codex | 只读 SQLite/JSONL 历史 + 桌面 IPC 实时快照和增量事件，明确区分待授权、等待输入、执行中 | 对应任务 |
| Claude Code | 会话日志及核验进程身份的运行态记录 | 有 TTY 时定位原终端；可识别 IDE 时打开项目 |
| Cursor | 已知 IDE SQLite、CLI 日志格式 | 有项目路径时打开 Cursor 项目 |
| Kiro | 新版会话事件及旧格式元数据 | 有项目路径时打开 Kiro 项目 |
| 通用 CLI | Aster 包装进程的心跳和真实退出码 | 可定位的 Terminal/iTerm 标签 |

当前已实机验证 Codex 和 Claude Code 读取。Cursor/Kiro 通过格式样例测试，这台电脑没有对应记录，尚未实机联调；旧 Kiro SQLite CLI 格式未支持，可用下述包装方式监控命令生命周期。

“本轮完成”只表示最新一轮明确结束，不代表长期目标全部完成。缺少明确状态或长时间没有更新时显示“状态未知/待核实”。实时待授权/等待输入不因超过三分钟而误判停止；连接断开后丢弃实时证据并回退记录。未发现任务来源会在设置及对应筛选空状态说明。

Codex 桌面 IPC 和各工具本地格式可能随版本变化；不支持的协议版本或增量序号断档会丢弃运行态并尝试重新订阅。只读监控不批准、接管或启动原任务。不会读取认证凭据或上传任务数据。任务列表仅返回展示所需元数据和公开文本。

## CLI 任务

以下示例在 Aster 项目根目录运行（Node.js 24+）；命令以当前工作目录执行：

```sh
node ./scripts/aster-run.mjs --title "构建项目" -- npm run build
node ./scripts/aster-run.mjs -- kiro-cli chat
```

Aster 不修改任何工具的 hooks、配置、可执行文件或 shell/PATH。卸载 Aster 不影响其他工具；包装脚本遇到监控目录不可用时仍照常执行原命令。

记录保存在 `~/.aster/tasks`（可用 `ASTER_TASK_HOME` 覆盖），保留原终端标准输入输出，不记录命令参数或输出。交互 CLI 的包装任务表示整个进程生命周期，各轮对话仍由原生适配器负责；已经启动的任意命令无法追溯退出码，需要下次使用包装命令。现有 Codex/Claude Code 会话无需包装。

详细范围与扩展接口见 [多工具监听说明](docs/multi-provider-monitoring.md)。

## 开发

```sh
npm ci
npm start          # 构建并启动桌面应用
npm run dev        # http://127.0.0.1:5178，?view=tasks 预览列表
npm test           # 状态、数据读取、只读 IPC、CLI 退出码及跳转测试
npm run package    # 打包当前 Mac 架构
```

浏览器预览不支持原生窗口和应用跳转。开发服务只绑定回环地址并校验 Host/Origin。

`core/all-readers.mjs` 聚合来源，`core/codex-live.mjs` 观察实时状态，`core/monitor.mjs` 在 Worker 内每三秒读取并合并快照；`electron/main.mjs` 管理两个独立窗口、通知及经过校验的跳转；`src/Robot.tsx` 使用 Three.js 渲染 3D 小机器人，WebGL 不可用时回退 SVG。后续语音、工具执行与记忆可独立订阅监控事件，目前尚未实现。

本地构建未做 Apple 签名或公证。素材和依赖来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 桌宠状态提醒

桌宠底部常驻显示「进行中 / 已完成 / 失败 / 待授权」及数量；有待输入、待确认任务时增加相应入口。点击任一状态会打开对应任务列表，列表中的任务可继续定位到原工具。「已完成」只表示任务最新一轮完成。

监测到新完成、失败、待授权、待输入或待确认时，桌宠显示可点击的提示，并在对应状态上保留新动态标记。查看某个状态只清除该类提醒；状态恢复或进入新一轮时，过期提醒自动清除。多个状态同时变化会分别保留，重复同步不重复提醒。启动时建立当前状态基线，不补发历史完成提醒；提醒队列保存在本次应用运行期间。

桌宠内的提示始终启用；设置中的「系统通知：完成、失败与待处理」单独控制 macOS 通知，需要系统允许 Aster 发送通知。

### 自定义缩放

在「伙伴设置 → 桌宠大小」拖动滑杆，可在 75%–150% 之间调整，每步 5%；100% 对应 200×320 的桌宠窗口。「恢复默认」可回到 100%。角色与状态条一起缩放，任务面板保持原大小，设置自动保存并在下次启动恢复。

### 开机启动

右键机器人 → 设置 → 开机启动。默认关闭；开启后在登录电脑时自动显示桌宠，关闭即移除 Aster 自身登录项。应用只在用户切换开关时改变系统注册，不覆盖系统设置中的手动关闭。若 macOS 要求允许登录项，设置页会显示提示；开发预览不注册 Electron 开发程序。应用移动或删除后，以系统“登录项”中的实际状态为准。
