# 维护规范与功能边界

本文件回答“这次允许改什么、改完怎样算完成”。功能入口见 [功能索引](features.md)，历史改动见 [变更记录](CHANGELOG.md)，日常使用见 [README](../README.md)。规则由项目 [AGENTS.md](../AGENTS.md) 引用。

## 1. 产品范围

Aster 是本机桌面任务观察工具：读取支持来源的状态与公开元数据，显示机器人、任务信息、Token、提醒，并在用户点击时定位原应用。CLI 包装入口只有在用户主动运行时启动指定命令。

不包含自动接管 Agent、自动批准请求、代发消息、执行任务建议、云端同步、费用结算、语音聊天或长期记忆。新增这些能力会改变产品边界，需要用户明确要求，并单独记录数据流和授权范围。

## 2. 修改权限与模块职责

| 修改类型 | 可以做什么 | 必须守住的边界 |
|---|---|---|
| 展示与交互 | 调整布局、文案、筛选、图标和可访问性 | 不在 UI 中猜状态或用假数据冒充真实任务；不把内部实现术语塞入用户流程 |
| 任务来源适配 | 增加已验证字段、兼容格式、修复解析和来源隔离 | 只读、限定读取范围；不能因为未知格式而把整个聚合服务判死 |
| 状态与提醒 | 修正状态证据优先级、去重、已读与过期清理 | 完成只指明确结束的最新一轮；启动不补发历史完成提醒 |
| Token | 读取来源用量、修正统计与展示 | 缓存不得重复累加；区分完整/近期、未知/0；不把 Token 换算为未经验证的费用或额度 |
| 任务定位 | 校验原会话、项目和终端定位入口 | 由用户点击触发；主进程从当前快照取目标，不接受渲染层传任意命令或脚本 |
| 自身开机启动 | 用户明确切换时注册/移除 Aster 自身系统登录项 | 不修改其他软件；不注册开发运行时；读取系统状态，不在启动时强制重注册 |
| 设置与历史隐藏 | 新增设置、合理默认值、兼容迁移 | 只写 Aster 自有设置；历史隐藏不删除来源记录，也不隐藏进行中和待处理任务 |
| CLI 包装 | 分类、心跳、进程身份核验和退出记录 | 原始输入输出直通；不捕获参数/输出；记录失败不妨碍原命令 |
| 打包与分发 | 重新构建源代码、刷新暂存副本、验证交付包 | 一次只有一个负责人；不手改生成物，不夹带个人信息、真实任务样例或本机目录 |

常规可逆修正在现有授权范围内完成。需要扩大外部行为、权限或破坏性影响时，先完成独立准备，再针对具体动作取得必要授权。

## 3. 路径、数据与隐私

### 路径来源

| 用途 | 正确来源 |
|---|---|
| 项目内文件、构建输出 | 从模块位置定位项目根目录，再拼接相对目录 |
| Aster 设置 | Electron `app.getPath('userData')` |
| 工具会话根目录 | 显式配置优先，默认使用 `homedir()` 与工具约定的相对目录 |
| 临时测试与失败样例 | `tmpdir()` + `mkdtempSync()`，结束只清理该测试创建的目录 |
| 运行 Node 或系统工具 | `process.execPath` 或按名称查找的系统工具；参数数组传递，不拼 shell 命令 |
| 文档与示例 | 仓库相对路径；跨项目运行时由用户在本机配置脚本入口，不把配置值写回仓库 |

HTTP 路由、TTY 格式校验、标准解释器声明不是个人安装目录。工具约定的相对目录名可以保留，但不能写死完整机器路径。运行时读取到的 cwd/TTY 是本地定位数据，不能成为源码、文档、测试 fixture 或发布附件。

不读取认证凭据，不上传会话数据；不会修改第三方 hooks、shell profile、PATH 或启动配置。隐私检查只输出相对文件名和违规类别，不输出被匹配的值。第三方依赖和许可证中的署名保留；不得借隐私清理删除法定署名。

`npm run check:privacy` 检查项目维护的文本。`npm run check:privacy -- --artifacts` 还检查构建输出、打包暂存区及各本地应用包中的文本。图片、音视频、二进制资源和真实日志截图需要人工确认；不能仅凭文本扫描宣称它们已脱敏。不要将开发用 QA 截图自动加入分发。

## 4. 一次修改的最小流程

1. **定位**：记录功能编号、用户目标、当前行为、计划改变的行为及受影响文件；小改动可直接写进对应变更条目，无须另建计划文档。
2. **实现**：只动必要文件。共享目录下编辑前重读相关片段；发现同时修改时协调文件及打包责任，不覆盖别人的工作。
3. **验证**：选下表中受影响的检查；修复失败后只复查相关范围，无新疑点不反复扩大验证。
4. **同步文档**：更新当前功能事实和一条变更记录。若范围改变，重写本条的结果，避免保留已经放弃的描述。
5. **交付**：给出实际产物和验证结论。桌面行为修改必须明确包是否更新、运行中的应用是否加载新包；无法确认时记录待验，不能写“桌面已生效”。

### 验证选择

| 影响范围 | 所需检查 |
|---|---|
| 纯文档 | 相对链接可解析、与当前代码一致、隐私检查；无需重新打包或重启 |
| 解析/状态/Token | 对应 `tests/` 用例；覆盖缺字段、重复事件、日志截断或重用进程等实际边界 |
| UI | `npm run build`，受影响交互与窄窗口布局；桌面专属交互在实际应用核对 |
| 设置 | 默认值、合法范围、旧值迁移、保存后同步与重启恢复；隐藏逻辑核对不删除记录 |
| 跳转/CLI | 参数校验、退出码、信号、记录不可写；跳转失败不能自动输入或重跑命令 |
| 分发 | 源隐私检查、构建、统一打包、生成物隐私检查；发布状态另行记录 |

命令均从仓库根目录执行：

```sh
npm run check:privacy
node --test tests/token-usage.test.mjs
npm run build
npm test
npm run package
npm run check:privacy -- --artifacts
```

这些是按影响范围选择的命令，不是每次都必须全跑的清单。包脚本自带分发前后隐私检查。只更新文档不触发应用重启。

## 5. 排查入口

| 问题 | 先看哪里 |
|---|---|
| 改了但桌面看不到 | 构建输出、打包暂存区与运行中的应用是否为同一版本；浏览器通过不能证明桌面更新 |
| 有会话但状态未知 | 对应 reader 的格式与结束证据，随后核对实时 IPC；不要改 UI 强行标记运行 |
| 某个工具消失 | `Snapshot.sources` 的连接/错误、来源目录、解析限制；其他来源应继续可用 |
| Token 很大或没有 | 核对累计/近期范围、缓存和消息去重；未提供不等于 0 |
| 老任务不见了 | 历史隐藏设置、来源归档/发现数量上限；不要自动删除或改写原任务 |
| 点任务没直达会话 | 原生会话与包装进程的 `observation`，再查项目/TTY 可用性 |
| 动画或缩放异常 | Robot、场景、共享动作配置、SVG 回退和尺寸计算；状态证据仍归 core |

## 6. 记录与回退

使用 [变更记录模板](CHANGELOG.md#记录模板)。每条记录带稳定编号和功能编号，方便全文检索。没有可靠历史证据的能力只记“基线盘点”，不编造上线日期、作者、提交号或实机测试。

回退以恢复对应源改动并重新构建为主。涉及设置格式时先确认旧版本能否读取；隐藏设置可恢复“始终显示”。没有可验证旧包或版本快照就如实写“无已验证回退包”，不承诺一键回退。
